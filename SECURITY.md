# Security Policy

## Supported Versions
Secure Architect Agent is maintained as a documentation-first, validation-first project. Security support is provided for the current main branch and the latest published release.

## Reporting a Vulnerability
If you discover a security issue, please report it privately to the maintainers instead of opening a public issue.

Include:
- A short description of the issue.
- The affected file or component.
- Why you believe it is security relevant.
- Any minimal reproduction steps, if available.

## What to report
Please report issues such as:
- Secret exposure.
- Unsafe defaults.
- Incorrect permission baselines.
- Broken validation logic.
- Supply-chain or dependency concerns.
- Security documentation gaps that could lead to unsafe adoption.

## What not to report publicly
Do not post security-sensitive details in public issues or pull requests.

Do not include:
- Secrets or credentials.
- Private keys.
- Internal system details that could expose infrastructure.
- Sensitive production data.

## Expected handling
Security reports will be reviewed as soon as practical.

If the issue is confirmed:
- We will acknowledge it privately.
- We will assess impact.
- We will prepare a fix or mitigation.
- We will publish relevant guidance when appropriate.

## Scope
This policy applies to:
- Repository structure.
- Documentation.
- Validation scripts.
- Example content.
- Prompts, workflows, and policy baselines.

## Good-faith behavior
We appreciate responsible disclosure and good-faith security reporting.
