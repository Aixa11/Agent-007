# Workflow: Publish

## Goal
Prepare the repository or project output for publication, adoption, or release.

## Trigger
Use this workflow when the user asks for:
- a release-ready package,
- publication guidance,
- repository cleanup,
- or a final presentation of the project.

## Steps
1. Confirm that the repository structure is complete.
2. Verify that documentation is coherent and consistent.
3. Ensure core files exist and are aligned with the project vision.
4. Check that examples and validation scripts are present.
5. Identify any missing publication blockers.
6. Prepare a concise release note or publication summary.
7. Return a publish-ready checklist.

## Output
The output must include:
- publication status,
- readiness summary,
- blockers if any,
- files that should be reviewed before release,
- and a final checklist.

## Constraints
- Do not claim release readiness if validation is incomplete.
- Do not publish secrets or sensitive data.
- Do not introduce unreviewed architectural changes during publication.
- Do not expand scope while preparing release material.

## Success criteria
- The project can be shared with a clear message.
- The repository looks coherent and intentional.
- The user knows what remains before release.
